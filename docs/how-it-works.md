# 工作原理

[首页](../README.md) · [使用指南](user-guide.md) · [开发指南](development.md)

PocketDesk 是 C# / WPF / Win32 实现。UU 负责远程连接、视频、输入与虚拟显示驱动；PocketDesk 读取当前连接证据、调整已有虚拟屏的模式，并管理选中的桌面窗口。

## 显示与控制者识别

`DisplayService` 读取显示设备、模式与 DPI。自动门槛要求 UU 适配器身份，不能只凭 Generic PnP Monitor、进程存在或屏幕尺寸确认连接。

`UuControllerService` 通过 Windows UI Automation 只读 UU 主页面的「本机被控中」范围。单个已知型号可映射到设备资料；None、Unknown 和多控制者分别处理。同账户其他设备列表不是当前连接证据。采样有时间戳和超时，迟到结果不能覆盖已经发布的超时状态；缺少 GUI 进程返回 Unknown，而非可靠断连。

`DeviceSessionPolicy` 将控制者、实际显示和设备资料组合。可靠 PC / 未知名称 / 多控制者不使用尺寸猜测。标准备用分辨率不会加入全局识别门槛；Unknown 续接只允许当前自动会话通过严格归属校验。

## 整帧与旋转

只缩小应用内部区域无法避开覆盖整帧的移动端控件，Windows 任务栏也不会随之移动。因此当前修改完整 UU 显示模式。

`PhoneScreenGeometry` 按设备像素和逻辑短边计算初次适配尺寸，使用居中对称边缘；不把 Windows DPI 再乘入设备物理比例。理想模式不可用时，`DeviceModePolicy.SelectSupportedFrame` 仅筛选驱动枚举中的安全候选。初次适配模式需要预检、应用和实际读回，API 成功本身不是最终完成。

手动旋转采用 `RotationModePolicy.SelectSwappedOwned`：从枚举中只选当前高 × 当前宽的精确尺寸，再核对设备 / 安全条件。当前已验证的手机组合为 1200×1920 与 1920×1200。缺少精确模式时不合成、不替换比例。旧方向选择策略仍有兼容测试，不代表当前手动入口行为。

应用库、窗口工作区和控制条使用实际工作区；界面内容缩放依据设备逻辑宽度。Windows 全局 DPI 和其他应用内部 UI 不被直接改写。

## 会话与恢复

`WorkspaceSession` 在原生写入前原子保存恢复日志。显示模式先记为 Pending，读回后才更新 Applied；始终保留第一次显示快照与窗口快照。模式归属含设备资料、留边偏好、原生 / 理想尺寸集合和本次显式选中的备用尺寸，每方向最多一档。加载时重新验证集合，损坏记录不能扩大修改权限。

窗口身份使用句柄、进程、启动时间、类和线程等证据。普通窗口按物理像素放置并要求稳定读回；应用最小尺寸会重新测量。最大化边框偏移只有在尺寸、状态、实测边框及可见工作区同时满足条件时才接受。无法确认则返回失败并保留记录。

常见备用分辨率可能与 PC 重合，所以自动恢复助手还需要新鲜控制者证据：Unknown / 过期 / 缺失时延后，完整日志不动；明确断连或同型号可恢复；PC / 其他型号 / 多控制者保留接管者显示模式。用户明确手动结束不受该未知证据等待规则阻止。

可靠 None 锁存断连，后续 Unknown 不立即重新认领。显示短暂重建不解除手动结束抑制或已消费的自动适配尝试。控制者一直 Unknown 且虚拟屏仍附着时，没有充分依据证明远程已退出。

## 能力边界

- 不提供手机端代理、方向传感器协议、原生手势 Hook 或虚拟显示驱动。
- 不保证兼容所有 UU 版本、应用最小尺寸、权限层级和虚拟桌面。
- 不保证恢复由 UU 管理的物理屏启用状态或拓扑；不把删除 journal 当成恢复完成。
- 未提供签名、自动更新或遥测服务。产品本地日志和设置应在公开分享前检查并脱敏。

架构与界面参考 [Snug](https://github.com/zephyr4123/snug) 的移动工作台思路，但 macOS 的 API、手机目录和输入重映射能力不等同于本项目。具体已验证范围以 [TESTING.md](../TESTING.md) 为准。
